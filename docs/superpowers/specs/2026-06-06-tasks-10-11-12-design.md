## Task 12 — Daily Finalization

### `assignDailyBadges(date: string)` — new function in `src/lib/finalization.ts`

1. Fetch `teammate_daily_stats` rows where `stat_date = date`
2. Call `calculateChad(stats)` → `chadId: string | null` (highest points)
3. Call `calculateChud(stats)` → `chudId: string | null`
   - **Chud is only eligible if the ship sank** — i.e. at least one teammate has `missed_required_tasks > 0`. `calculateChud` already enforces this by filtering to `eligible = stats.filter(s => s.missed_required_tasks > 0)`. If the ship survived (everyone completed all required tasks), `eligible` is empty and Chud is null.
   - Among eligible: lowest points first; tiebreak by most missed tasks; tiebreak by teammate ID
4. Clear all `current_chad` and `current_chud` flags on `teammates` table (set both to `false` for all rows)
5. If `chadId` is not null: set `current_chad = true` on `teammates` where `id = chadId`; also update `is_chad = true` on the matching `teammate_daily_stats` row
6. If `chudId` is not null: set `current_chud = true` on `teammates` where `id = chudId`; also update `is_chud = true` on the matching `teammate_daily_stats` row

### `finalizeDay(date: string)` — in `src/lib/finalization.ts`

Idempotent — safe to call multiple times for the same date (uses upserts).

Steps:
1. Fetch all active teammates (`is_active = true`)
2. Fetch all `daily_tasks` for `date` across all active teammates
3. Fetch all `task_completions` joined to those tasks
4. For each teammate, compute:
   - `points_earned` — sum of `points_awarded` from their completions
   - `total_required_tasks` — count of their required `daily_tasks`
   - `completed_required_tasks` — count of their required + completed `daily_tasks`
   - `missed_required_tasks` — `total_required_tasks - completed_required_tasks`
   - `completed_all_required` — `missed_required_tasks === 0 && total_required_tasks > 0`
5. Upsert one row into `daily_results` (one row per date, covers the whole team):
   - `result_date`
   - `outcome`: `'survived'` if every active teammate with required tasks completed all of them, else `'sunk'`
   - `completion_percentage`: `calculateTeamProgress` across all teammates' required tasks
   - `total_required_tasks`, `completed_required_tasks`, `missed_required_tasks` (team totals)
   - `chad_teammate_id`, `chud_teammate_id`
6. Upsert one row into `teammate_daily_stats` per teammate:
   - `teammate_id`, `stat_date`, all computed fields above
7. Call `assignDailyBadges(date)`
8. Call `createNextDayRecurringTasks(date)` (already implemented)

### Auto-trigger on app open

In `src/app/page.tsx`, inside the existing `fetchData` function (called on mount):
- After fetching today's data, check if a `daily_results` row exists for `yesterdayString()`
- If not, call `finalizeDay(yesterdayString())` silently (no loading state, errors swallowed — it's a background housekeeping step)
- After finalization completes, re-fetch data so badge state on the dashboard reflects the update

Write failing tests for `assignDailyBadges` and `finalizeDay` before implementing. These will be integration-style (mock Supabase client) in `src/__tests__/finalization.test.ts`.

## Task 11 — Admin Dashboard

### Route
`src/app/admin/page.tsx` — client component

### Authentication gate (unauthenticated state)

Full-screen Arctic scene:
- Same gradient background as `/login` (`#061826` → `#0B3558`)
- 30 pre-computed star positions (no `Math.random()`)
- Two icebergs (`animate-float`)
- Animated wave layer at bottom
- Faint ship silhouette (low opacity, decorative only)
- Frosted centred panel: "⚓ Admiral's Deck" title, subtitle, code `<input>`, "Board →" button

On submit:
- Call `validateAdminCode(input)` from `src/lib/auth.ts`
- Success: `sessionStorage.setItem('admin_authenticated', 'true')`, set `authenticated` state to `true` (reveals dashboard in same page — no navigation)
- Failure: show `IcyErrorModal`

On mount: read `sessionStorage.getItem('admin_authenticated')` — if `'true'`, skip gate and show dashboard directly.

## Key Constraints

- All new modals use `<IcyModal>` — do not hand-roll backdrop/card styles
- `finalizeDay` must be idempotent (upserts throughout, not inserts)
- Admin session uses `sessionStorage` (intentionally short-lived per tab)
- No `Math.random()` in any component rendered server-side (hydration mismatch)
- `params` is a `Promise` in Next.js 16 — use `React.use(params)` in client components
